# OS ACTIVE STANDARD , the one definition, codified
A layer/tool/route is ACTIVE only if the OS can, with a proving artifact:
1. know when to use it   2. route to it   3. call it or hand off to it   4. log the action
5. validate the result   6. store the artifact   7. update the dashboard   8. repeat the workflow

Status taxonomy (every layer must carry one):
- ACTIVE: all 8, proven by an artifact.
- AMBER: connected/installed/partial, missing at least one of the 8 (e.g. needs handoff or upload).
- RED: not present / not callable.
- DEFERRED: deliberately postponed by the operator.

The OS must NEVER again confuse: notes with capability, access with capability, plugin visibility
with workflow, read with certification, generation with production, pretty output with shippable
output, provisional doctrine with truth, or an old lane with destiny.

SHIP) and now the os_engine one-intent run (DEED OFFICE: campaign SHIP, privacy SHIP, money 84).
