## B1 · Client-grade landing page
- **Purpose:** test whether web deliverables can enter the client/offer stack.
- **Task:** one SNIPED-voiced landing page for a real existing offer context, using the locked positioning phrases.
- **Expected artifact:** single self-contained HTML file, mobile-responsive.
- **Tools:** HTML/CSS only; browsers for verification.
- **Pass/fail gate:** passes /sniped-positioning-phrases diagnostic AND renders clean in Chrome + Safari at 390px and 1440px. Voice gate (no em-dashes, no AI-tell).
- **Est. time/tokens:** 20-40 min; modest token use; 0 credits.
- **Proves for BJ:** a sellable web deliverable is one prompt away with his voice discipline intact.
- **Does NOT prove:** that anyone will pay for it (demand evidence is the ledger's job).

## B2 · Report recreation from real source material
- **Purpose:** test the consulting-lane deliverable format (independently validated: Riley Brown ran this exact test against a McKinsey PDF).
- **Task:** regenerate one existing OS report as a designed HTML/print-PDF document with charts built from real numbers on disk.
- **Expected artifact:** HTML report + print-to-PDF, inline SVG charts.
- **Tools:** HTML/SVG; Chrome print. No CDN required.
- **Pass/fail gate:** every number traceable to a source file on disk (zero invented data) + adversarial-verify pass on accuracy and design quality.
- **Est. time/tokens:** 30-60 min; 0 credits.
- **Proves for BJ:** the consulting deliverable format exists on demand from HIS data discipline.
- **Does NOT prove:** consulting demand, McKinsey-equivalence of analysis (format is not insight).
