# 03 ADOBE OPERATIONALIZATION
> The Adobe MCP bridge is LIVE as a tool. None of it is wired into a repeatable OS workflow yet. This is the plan to operationalize it.

Brutally honest verdict: the Adobe capability is 0% operationalized today. Verified on disk: no os_adobe.py, no python file anywhere calls any Adobe MCP tool (grep for image_adjust / image_apply_preset / document_render / video_create_quick_cut / Adobe_for_creativity across all .py returned nothing), and every one of the 10 named skills routes to MANUAL desktop apps (Lightroom Classic, Evoto, Photoshop) or to Higgsfield/Seedream/Nano Banana for generation. None invoke the Adobe bridge. The ONLY Adobe MCP references on disk are doctrine notes (OS_CAPABILITY_MAP lines 510/759/773/777, OS_CAPABILITY_TOOL_ROUTING lines 17-40) and recipe sketches (MONEY_PLAYS_OS_x_TOOLS). Per the activation contract those are notes, not capabilities, so the correct status for grade/composite/layout/video/export via Adobe is known_not_operationalized / needs_adobe_wrapper. The live MCP bridge means the plumbing connects, nothing more. What is genuinely strong and ready to harvest: the parameter content is already locked and specific (v3 LUXURY slider math in the .xmp and sniped-luxury-edit, the 9 export presets, the 8-gate COMPOSITE_MASTER_QA law, the Photoshop gap audit setting the MCP ceiling boundary). That means wrapping is mostly plumbing plus encoding existing locked values, not new doctrine. Recommended build order: (1) os_adobe_asset.py I/O layer first since every other wrapper needs clean file-in/file-out; (2) os_adobe_grade.py with SNIPED_LUXURY_GRADE.json driving image_adjust_* in the locked 10-step order, gated by os_vision_gate so output must beat source; (3) os_adobe_reframe.py with SNIPED_EXPORT_SPECS.json from the 9 locked presets (cleanest first real dry-run, specs already locked); (4) cutout + composite lane wired into the existing composite-master-qa gates; (5) document_render layout (greenfield, zero template on disk) and video edit last. Hard guardrails to carry from the doctrine into every wrapper: identity layer stays manual (hard refusal on identity-AI for client work), no teal/orange, Adobe Neutral baseline, 6-attempt generative cap empty-prompt-first, and the strongest-photograph reject gate so no automated output ships unless it beats the source. Each wrapper counts as ACTIVE only once it has a script, a parameter/template file, a test or logged dry-run, and a registry entry in OS_SKILL_REGISTRY; until then mark INSTALLED_INCOMPLETE.
