## 7 · Extraction method by file type

The extraction step normalizes every source into a plain-text `.md` or `.txt` file under `01_KNOWLEDGE_BASE/batches/batch_005_extracted/`. The normalized filenames follow lowercase-snake-case (e.g., `sontag_on_photography.md`, `barthes_camera_lucida.md`, `study_annie_leibovitz.md`).

### Per-format extraction recipes

| Format | Tool | Command pattern | Notes |
|---|---|---|---|
| `.md` | none (copy) | `cp` to normalized name | Already plain text · just rename + strip front-matter if any |
| `.txt` | none (copy) | `cp` to normalized name | Already plain text |
| `.docx` | `pandoc` | `pandoc -f docx -t plain -o <out>.md <in>.docx` | Preserves heading structure |
| `.epub` | `ebook-convert` (calibre) | `ebook-convert <in>.epub <out>.txt` | Cleaner than `pandoc` for epub; preserves chapter breaks |
| `.mobi` | `ebook-convert` | `ebook-convert <in>.mobi <out>.txt` | Same |
| `.pdf` (text layer) | `pdftotext -layout` | `pdftotext -layout <in>.pdf <out>.txt` | Inspect first 2 pages to confirm text layer is present |
| `.pdf` (scanned) | `tesseract` OCR via `ocrmypdf` | `ocrmypdf <in>.pdf <out-ocr>.pdf && pdftotext -layout <out-ocr>.pdf <out>.txt` | Slower. Apply only if `pdftotext` returns gibberish or empty. |
| `.mp4` | (defer) | Whisper transcription · NOT in this batch | Defer to BATCH_010 |

### Per-source extraction decision

The Priority 1 + 4 source set:
- 4 epubs · use `ebook-convert`
- 2 mobi · use `ebook-convert`
- 4 PDFs with text layer (Sontag, Shore Nature, Day Frank-as-EPUB, Szarkowski Eggleston intro) · use `pdftotext -layout`
- 1 PDF scanned + text mixed (Avedon American West journal, Fred Herzog journal, Robert Frank Art Book journal) · pdftotext first, OCR fallback per source
- 1 PDF mixed (Hughes/Haas hardback) · pdftotext, isolate essay sections

Priority 2 source set:
- 19 .md / .docx · 18 native md (copy) + 1 docx (pandoc)

Priority 3 source set:
- 1 scanned PDF (Cartier-Bresson) · pdftotext probe first, OCR if needed
- 1 .txt (Abloh lecture) · copy

### Post-extraction sanity check

After extracting each source, the extraction script must report:
- byte count of the input
- byte count of the extracted .txt/.md
- word count of the extracted text
- if word count < 500 for any source, surface as a warning before chunking begins

This catches scan failures, encrypted PDFs, and visual-only sources that leak into the inclusion set.

