## 7. Keep / kill / iterate rules

- **KEEP** when a hypothesis shows repeated real-world proof: paid + referred/repeat + used. Repetition matters more than a single win.
- **KILL** when, after a real test, there is only free interest, no willingness to pay, or no adoption. A clean kill is a win; it frees reps for a better hypothesis.
- **ITERATE** when there is a partial signal worth refining: valued-but-not-bought, adopted-but-unpaid, right-idea-wrong-buyer, or right-buyer-wrong-offer. Change one variable and re-test.
- **Canonization rule:** a direction is canonized only after the log shows repeated proof, never by argument or by corpus depth. Until then it stays a live option.
- **Anti-hiding rule:** if a week passes with new reading but no new proof-log entry, that is a flag, not progress. Ingestion is not a substitute for reps.

## 10. Weekly review protocol

Once a week, in this file:

1. **Log reality.** Add any real completed tests to §6 (the proof log). If nothing real happened, write that down honestly.
2. **Update statuses.** Move §2 hypotheses across UNTESTED -> TESTING -> KEEP/KILL/ITERATE based on the log, not on hope.
3. **Check the boxes.** Update the §3-5 checklists; note signals observed.
4. **Apply the rules.** For each active hypothesis, make a keep/kill/iterate call (§7). Kill cleanly when warranted.
5. **Anti-hiding check.** Did this week add a proof-log entry, or only more reading? If only reading, name the next real test and schedule it.
6. **Carry the open questions.** Update §8 with anything reality answered.
7. **Hold the line.** Confirm nothing got prematurely locked; the held material (§9) stays held.
