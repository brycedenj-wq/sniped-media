# OS_INPUT_PROTOCOL_FOR_BJ (2026-06-08)

How to prompt the OS so it unlocks the whole body every time. You should never have to ask "did you use the whole OS?" The conductor shows it automatically. But the better your input, the better the output. Here is exactly how to feed it.

## The truth about activation
The OS auto-scans on every turn (the [OS ACTIVATE] block). Serious tasks auto-trigger MAX mode + cross-domain pull + an OS_RECEIPT. You do NOT have to name skills. You CAN force max by saying so. You only need to give the OS the few decisions it cannot infer.

## Prompt tiers (use the one that fits)

**Minimum prompt** (the OS still scans + routes):
> "<what you want>." e.g. "Make the Synergy film."

**Best prompt** (add outcome + audience + the one thing):
> "<deliverable> for <audience>. The one thing it must do: <X>. Platform: <Y>. Assets attached."

**Production prompt** (client-facing, MAX by default):
> "Production: <deliverable> for <client/audience>. Outcome: <X>. Platform(s): <Y>. Deadline: <when>. Budget: <if any>. Assets: <paths>. Must be 10/10. Show me the OS receipt."

**Emergency prompt** (compressed, not careless):
> "Emergency, due <time>, budget <$>. Deliverable: <X>. The one thing that must be excellent: <Y>. Cut scope not quality. Label it honestly."

**Max capability prompt** (force the ceiling on anything):
> "Max capability / go all out on <task>. Pull cross-domain. Target 10/10, name what blocks it."

**Use the whole OS prompt**:
> "Use the whole OS on <task>." (also: "whole os", "conductor mode") -> forces full-registry scan + receipt.

## What to include (assets/decisions)
- **Assets:** reference images, brand/preset files, footage paths, the brief PDF, prior versions. Paths or attachments.
- **Decisions only you can make (state upfront):**
  - the ONE outcome / what the audience judges it on,
  - audience + platform,
  - deadline + budget,
  - mode (max vs emergency) if not obvious,
  - any hard brand/identity constraints,
  - send target (client / internal / proof / social).

## What the OS should infer WITHOUT asking you
- which domain(s) and skills apply, and the cross-domain pulls,
- the standards, gates, and toolchain,
- the production loop and the proof/receipt requirements,
- format/aspect defaults from the platform,
- that serious/client work is MAX mode and needs a receipt,
- the anti-gloss / identity-untouched / no-em-dash laws.
If a REQUIRED decision is missing (deadline for an emergency, the one outcome, a usage/release for casting), the OS asks for that one thing, then proceeds. It does not ask you to re-supply the goal or name skills.

## What you get back on serious work
The OS receipt: what it considered (whole registry), what activated, what stayed asleep + why, what CHANGED because of activation, gates passed/failed, the honest rating, what blocks 10/10, and the verdict. If it is not 10/10, the blocker and the path are named. Nothing serious is called "done" without this.

## One-liners to keep in your pocket
- Ceiling: "Max capability, 10/10, show the receipt."
- Fast: "Emergency, due <time>, protect <the one thing>, cut scope not quality."
- Whole system: "Use the whole OS."
