# OS EXTERNAL VISUAL PROOF GATE

Status: LIVE doctrine (2026-06-19). Authority over all visual-production final-judgment. Wired into the router via `OS_ACTIVATION_INDEX.json` gates (film, photo_composite, editing_retouch, brand_campaign) and `OS_ROUTER_INDEX.md`.

## The rule

Claude is NOT the final visual authority. Claude's visual layer is not fully trusted for taste, image quality, motion weirdness, face drift, or client-facing visual judgment. ChatGPT and Gemini often inspect images and video with better taste and higher fidelity, and the operator's eye outranks all of them.

## What Claude MAY do
1. Coordinate, inventory, sequence, prompt, document, and build handoffs.
2. Do first-pass visual triage (flag obvious morphs, garbled text, broken hands, continuity breaks).

## What Claude MAY NOT do
3. Crown visual quality alone. Claude cannot call visual work final, ready, clean, premium, client-safe, or approved based only on its own visual read.

## When the gate is REQUIRED
Any serious photo, video, composite, AI-motion, campaign, client deliverable, or portfolio-facing artifact must pass an External Visual Proof Gate before it can be called final/ready/client-safe.

## What counts as passing the gate (one or more)
- Operator visual approval.
- ChatGPT visual review.
- Gemini visual review.
- A side-by-side contact sheet / frame strip reviewed outside Claude.

## Claude must make outside judgment easy: the REVIEW PACKET
Before sending visual work to a judge, Claude produces a packet containing:
- A contact sheet and/or frame strip (numbered).
- Shot IDs / filenames mapped to the frames.
- Explicit reject criteria (face drift, morph, garbled text/plates, waxy skin, continuity break, weak composition).
- Before/after notes where relevant.
- The exact questions for the visual judge (what to confirm, what to kill).

## Status discipline (client-facing)
6. If the External Visual Proof Gate has NOT been passed, status stays `draft` / `internal` / `not-ready`. Never `final`, `client-safe`, or `approved`.
7. This composes with, and sits ABOVE, `os-vision-reject-gate` (which is Claude's first-pass triage only) and the Production Completion Enforcer / PROOF_MANIFEST. A PROOF_MANIFEST for a visual deliverable is not complete until it records who ran the external visual gate and the verdict.

## One-line enforcement
No visual artifact is crowned on Claude's eye alone. Build the packet, route it to an external visual judge (operator/ChatGPT/Gemini), record the verdict, then and only then label it.
