# OS_VISUAL_PRODUCTION_LAW (permanent)

Installed 2026-06-27 by operator directive. Applies to every visual the OS produces, forever. Pairs with `OS_TOOL_ROUTING_STANDARD.md` and `OS_EXTERNAL_VISUAL_PROOF_GATE.md`.

## The law

No weak or basic render may represent the OS, a universe, a client package, or a proof artifact. Basic output is allowed ONLY as scaffolding (an internal production step). Premium output is the bar for anything public, proof-facing, client-facing, or universe-facing.

A basic render may exist only as an internal step: blockout, form study, lighting test, material test, reference test, rejected draft, or source-of-truth construction pass. It may NEVER be labeled or treated as: final, premium, proof, hero, client-ready, case-ready, launch-ready, universe output, or finished asset.

## Every visual gets one honest classification

1. **BLOCKOUT** : rough geometry/layout placeholder.
2. **FORM STUDY** : shape/silhouette proof, no finish.
3. **LOOK TEST** : material/lighting/color test.
4. **SOURCE-OF-TRUTH SYSTEM** : the reference construction (the parametric source other tools render from). Reference, not output.
5. **PRODUCTION DRAFT** : a real attempt at the asset, not yet premium.
6. **PREMIUM CANDIDATE** : premium quality, pending the acceptance gate.
7. **ACCEPTED ASSET** : cleared the gate; the only class allowed on public/proof/client/universe surfaces.
8. **REJECTED** : failed; kept only as a record, never used.

## The ACCEPTED ASSET gate (all must clear; no self-crown)

A visual moves to ACCEPTED ASSET only when it clears:
- brand / world consistency
- visual quality
- material believability
- composition
- typography / label / text integrity
- artifact / slop check
- source-feature landing (the thing it must prove is actually visible)
- business usefulness
- External Visual Proof Gate (external reviewer on a frame-strip packet; Claude is not the final visual authority)

## Tool-routing law (pro route, not easiest callable route)

For every serious visual, answer in order:
1. What would a professional creative shop do?
2. What is the best route if quality is the priority?
3. What can Claude execute directly (callable)?
4. What requires Adobe / Firefly / Photoshop / Illustrator / Lightroom / Figma / Blender / Higgsfield / manual operator work?
5. What gets built now while the manual or spend steps wait?
6. What is the rejection bar?

Never settle for an MCP limitation. Never present an internal test as proof. Never call a blockout a deliverable. Never grade automated slop as premium. Never move a visual onto a site/deck/social/proof surface unless it has earned ACCEPTED ASSET status.

## Enforcement

- Every render folder carries a classification (a `VISUAL_CLASSIFICATION_LEDGER.md` or per-file class tag).
- Public/proof/client/universe surfaces import from an `accepted/` set only. Reference and tests live in `_reference/` or `_tests/` and are never embedded as finished assets.
- The Stop/completion enforcer treats "hero/final/premium/client-ready/proof" claims on a non-ACCEPTED visual as a false completion.
