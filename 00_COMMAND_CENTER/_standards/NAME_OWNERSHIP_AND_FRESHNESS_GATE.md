# NAME OWNERSHIP + FRESHNESS GATE (permanent, hard front gate)

**Installed:** 2026-06-26 · Naming and ownership are a hard gate BEFORE a name is used as a product name, folder title, deck title, site title, or offer title. Not a late polish item. A name that survives only because it reads clean in a document has failed. Most clean-sounding names are owned ten times over and feel generic; assume that until proven otherwise.

## The ten checks

A serious name must be evaluated against all ten. Each is PASS, FAIL, or UNVERIFIED.

1. DOMAIN AVAILABILITY. Is a usable domain actually free. Check by searching and by seeing if the domain resolves. True registration status needs a registrar or WHOIS check; if that is not done, label UNVERIFIED, never available.
2. SOCIAL HANDLE AVAILABILITY. Are the handles free on the platforms that matter. If not actually checked, UNVERIFIED.
3. SEARCH UNIQUENESS. Does the name return a crowded field or a clean one. Many existing users is a FAIL.
4. TRADEMARK RISK / OBVIOUS EXISTING USE. Is there an obvious active business using it, especially in or near the category. Obvious existing use is a FAIL or HIGH RISK.
5. CATEGORY FIT. Does it fit the work without colliding with an existing name in the same category. A same-category collision is the worst case.
6. FRESHNESS WITH THE CURRENT CULTURAL MOMENT. Does it feel current, or like a played-out naming trope.
7. VOICE FIT WITH THE OPERATOR. Does it sound like BJ (plain, direct, confident, raw, specific), not like a committee.
8. CUSTOM, NOT TEMPLATE. Does it feel made for this one thing, or could it be any brand.
9. AVOIDS GENERIC AGENCY WORDS. Avoid house, studio, lab, collective, agency, atelier unless there is a strong, specific reason. Default FAIL if it leans on one of these.
10. DOES NOT SOUND LIKE A RANDOM LUXURY / AI / CREATIVE AGENCY NAME. If it sounds like the hundred other clean creative-agency names, FAIL.

## Zero-spend checks you MUST run (do not punt these to UNVERIFIED)

Public availability research is free and is required, not optional. At zero spend you can and must check: public search, obvious existing use (especially in or near the category), social handle signals (search the handle, see if a profile exists), and domain availability SIGNALS (search the domain, fetch it, see if a real site resolves). Run these and report the real signal. Only label something UNVERIFIED when confirming it would require an actual registrar purchase, an account login, a reservation, or a legal review. Those are APPROVAL-REQUIRED, not UNVERIFIED-by-laziness.

## Hard rules

- Run the zero-spend checks. Only claim a domain or handle is truly secured after a registrar or account action, which is APPROVAL-REQUIRED. A free site-resolves check that finds nothing is reported as "no obvious site found, likely open, registrar check APPROVAL-REQUIRED," not as UNVERIFIED.
- Do not crown a name from vibes. A name is only adopted after it passes the hard checks (3, 4, 5, 9, 10 at minimum) AND clears 1, 2 as verified-free or is explicitly accepted by the operator with the risk known, AND passes operator taste (6, 7, 8).
- Do not generate public-facing assets around an unverified name.
- Do not build the brand identity around a name before it passes the gate.
- Until a name passes: use a neutral internal codename only (for example THE_HOUSE). The codename is for folders and internal docs, never public.

## Verdict labels (per candidate)
- FAIL: obvious collision, generic, or wrong voice. Drop it.
- WEAK: a possible collision, or not fresh or distinctive enough. Not presented as a real option.
- UNVERIFIED: cannot be confirmed without a login, a registrar action, or a legal check (APPROVAL-REQUIRED). The zero-spend signal was run; only the paid or gated confirmation remains.
- PASS-CANDIDATE: no obvious collision found in the zero-spend checks, voice-fit is strong, distinctive. NOT adopted until the operator approves and any APPROVAL-REQUIRED confirmation is done.
- PLACEHOLDER: a temporary codename, never the real name.

If no candidate reaches PASS-CANDIDATE, the slate is bad. Say so plainly and regenerate. Never ask the operator to pick from a slate of WEAK or FAIL names.

## Process
1. Generate candidates in the operator's voice, deliberately avoiding the banned generic words.
2. Run the ten checks, doing the real availability and uniqueness checks (search, resolve the domain, look for existing use) rather than guessing. Label anything unchecked UNVERIFIED.
3. Only a name that reaches PASS plus operator taste approval is adopted. Everything else stays a PLACEHOLDER and the codename holds.
