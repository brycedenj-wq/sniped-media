# OS MONEY PLAY GATE (authority for the money_play domain)

The automatic behavior contract for ANY money / product / venture / cash-play / AI-business / automation / scale / monetization question. Fired by `os_activate.py` via the `money_play` domain in `OS_ACTIVATION_INDEX.json`. The operator should NEVER have to ask for this by hand again. Executable, not prose.

## When this fires
Any prompt about: making money, a product, a venture, a cash play, an AI business, automation, scale, monetization, revenue, income, an offer, pricing, selling, or productizing. (Triggers live in the `money_play` domain `match` list.)

## VALUE CHAIN (the default frame, read first)
1. **Corpus = ingredients.** Every doc, book, file, video, tool, connector, skill, workflow, and doctrine layer.
2. **OS = kitchen.** It turns ingredients into outputs.
3. **Owned world/product = the meal.** The deliverable is an OWNED, audience-facing world / product / IP the operator controls.
4. **Audience/revenue = market response.**

HARD RULE: **Do NOT recommend selling the internal ingredients** (SREF packs, prompt packs, doctrine packs, book summaries, workflow notes, internal field manuals, the OS itself) unless the operator EXPLICITLY asks. The corpus is the ingredients, not the product. Use the corpus to BUILD an owned output. Selling the recipe is off by default; selling the meal (the world, the characters, the story, the finished editions, the audience experience) is the goal. If a play's product IS a corpus ingredient repackaged, it is DISQUALIFIED unless the operator asked for it.

## The 7 mandatory steps (do all, in order, before answering)
1. **Route through the money doctrine stack:** money/offer (`OS_MONEY_OFFER_DOCTRINE.md`), pricing (`OS_PRICING_GATE.md` + the `pricing_offer` pack), copy (`COPY_DOCTRINE_CAPLES_TESTED_ADVERTISING.md` + the `copy` pack), status/luxury (`status_psychology`), creator economy (`CREATOR_AI_PRODUCTION_FIELD_MANUAL/FIELD_MANUAL.md`), leverage (`sniped-leverage-logic`), trust/sales (`trust_sales` pack).
2. **Retrieve the bound material:** Start Here money/content/AI-tooling (`OS_STARTHERE_DOCTRINE.md`), AI-money plays (`MONEY_PLAYS_OS_x_TOOLS_2026-06-02.md`), workflow/capability routing (`OS_CAPABILITY_TOOL_ROUTING.md`, `OS_OFFER_STACK.md`, `OS_PROOF_TO_CASH_ROUTER.md`), connector + tool-readiness (`OS_TAKEOVER_PHASES_001/OS_TOOL_READINESS_LAYER.md` + `OS_TOOL_APP_INTEGRATION_LEDGER.csv`), outreach (`_reference/COLD_OUTREACH_ATOMS.md`). Do NOT re-run source waves; pull from bound doctrine.
3. **Include a SOURCE + TOOL BASIS table** (per play): doctrine used · exact source file · confidence label · app/tool/connector · readiness label · what manual work it removes · how the OS executes or reduces the work.
4. **Label every tool/app/connector** honestly: `ready` (no spend, no approval) · `untested` (live but no proving run) · `approval-gated` (external send/deploy/post, held by policy) · `spend-gated` (costs credits/subscription) · `unavailable`. A play needing spend/send/deploy is NOT ready. Ground labels in the tool ledger, do not invent.
5. **Rank options.** DEFAULT (build-the-meal) mode: rank by quality of the owned asset · speed to test · low manual effort · employer safety · monetization potential · $300k/year path. Only when the operator EXPLICITLY asks for a cash play / service does the secondary axis (speed to money · repeatability) lead.
6. **Build owned outputs, not ingredient resale.** Each output is an OWNED world / product / IP the operator controls, built FROM the corpus (show which doctrine + tools feed it as ingredients). Downgrade bespoke service labor unless explicitly chosen. KILL: ingredient-resale (selling the corpus) unless asked, custom-puzzle-per-sale, SNIPED Media / photo default, or anything that is not an owned asset.
7. **Return** (where relevant): the owned world/product concept + which doctrine/tools feed it + the first 7-day world/product artifact to build + monetization path + employer-safe/faceless check + kill criteria + $300k/year math (honest margin). For an EXPLICIT cash play also give exact offers (3-option anchor), exact messages (copy-clean, no hype, no em-dash), delivery steps, automation path.

## Hard laws
- VALUE CHAIN: corpus = ingredients, OS = kitchen, owned world/product = the meal, audience/revenue = market response. The default deliverable is an OWNED output built FROM the corpus, never the corpus itself. Do NOT recommend selling internal ingredients (SREF/prompt/doctrine packs, book summaries, workflow notes, field manuals, the OS) unless the operator explicitly asks; such a play is disqualified by default.
- A play that cannot cite bound doctrine AND a concrete OS/tool advantage is DOWNGRADED.
- Confidence labels: `certified` = pricing/copy/offer($100M)/Mom-Test/status_psychology/leverage/hospitality. `source_uncertified` (label, never sole anchor) = trust_equation/new_luxury/hit_mechanics. `provisional_chunked` = other books + scrape-dated field-manual tool names/costs. `project-context` = this project's own docs.
- Payment follows proof. Hold the floor (trade scope not price). No spend / send / deploy / post / generation / payment rails before a real yes AND operator approval.
- Employer-safe only: no employer workflows/customers/vendors/facilities/data/QA/commissioning/site. Engineering mind is a thinking style, not the customer lane.
- No lane crown: cash plays are TESTS with kill criteria.
