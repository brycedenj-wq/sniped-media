# OS_TRANSFORMATION_ROUTER

**Date:** 2026-05-26
**Status:** Mandatory operating layer for all future Command Center work. NOT a business strategy, NOT chunking, NOT a master update. An execution router that turns the OS into an active transformation engine. Anchor-class: markdown-only, not chunked, not in the master files.
**Read-first partner:** `COMMAND_CENTER_COVERAGE_MANIFEST.md` (what exists, by job). This router is HOW to use it on every task.
**Why this exists:** the OS was twice underused (a generic Carrd recommendation; the `14_WEB` build kit ignored before the site build). This router makes routing through the OS non-optional so output is unfairly better than generic AI, without blindly rereading everything.

---

## 1. Operating premise

- BJ's OS is an **advantage, not an archive.** 1,837 chunks, the Command Center, the tool docs, the held context, and the live execution state exist to make output unfairly good.
- Every book and doc **may be transformative when routed correctly.** The value is in pulling the right lane at the right moment, not in volume.
- Claude must use **books + docs + tools + BJ context together**, not one in isolation.
- **No generic advice while relevant OS material exists.** If the OS has a doc or asset for the task, use it before any default. The Carrd miss is the cautionary case: a no-code default was offered while a full `14_WEB` build kit and Claude-Code build capability sat unused.

## 2. The transformation router (run this on every task)

1. **Detect task category** (section 3).
2. **Select doctrine lanes** from the canonical corpus (via MASTER_INDEX / ACTIVE_KNOWLEDGE_STATE, not raw rereading).
3. **Select tactical docs** (Command Center artifacts for this job).
4. **Select tool/app docs** (the relevant tool kit: `14_WEB`, n8n, brand kit, etc.).
5. **Load BJ context + proof-loop state** (CURRENT_OPERATOR_REALITY_BRIEF, the synthesis, PROOF_LOOPS_30_60_90, employment/IP constraints).
6. **Perform or propose** the task using all of the above.
7. **Report OS resources consulted** (section 8).
8. **Report relevant resources skipped and why.**
9. **If a major job-specific resource was not consulted, STOP and consult it before final output** (this is what the site build missed).

## 4. Book / corpus activation rules

- Use `MASTER_INDEX.md` narrative sections and the per-lane `summaries/` + `indexes/` first.
- Activate the relevant lanes for the job; do not raw-reread by default.
- Inspect raw book/source text only when a decision depends on specific material a summary lacks.
- Combine strategy, money, psychology, systems, aesthetics, operator doctrine, and tooling when the task spans them.
- Never let one book or doc dominate current proof reality. The proof log outranks any source.

## 5. Tool-doc activation rules

- **Site task -> check `14_WEB` + the Claude-Code-website-building docs + the Brand Bible.** (The miss that triggered this router.)
- **Automation task -> check N8N_AUTOMATION_SYSTEMS / n8n / Twilio / API docs** (then almost always park).
- **Content task -> check distribution/platform docs + AI-content tool docs** (Higgsfield/Kling parked).
- **Outreach task -> check LinkedIn / Instantly / email docs + the live context tool stack.**
- **Design task -> check the brand kit + `14_WEB` visual references + UX/CRO docs.**
- **If relevant tool docs exist and are skipped, Claude must say so before finalizing.**

## 6. Claude Code build standard

- **Build first** when the task is code/site/system and the repo/assets make it practical.
- **No-code is a fallback, not a default.**
- **Apps for commodity infrastructure only:** scheduling (Calendly), payments + contracts (Pixieset), email (Google Workspace), outreach (LinkedIn/Instantly). Do not rebuild these.
- **Static before app.** A landing page is static HTML/CSS, not a framework.
- **App only when proof demands it.** No overbuild before proof.

## 7. Anti-failure rules

- No Carrd or default-tool recommendation without checking the OS and Claude's own build capability.
- No generic AI advice while relevant OS material exists.
- No endless docs when a proof action is available; the proof log is the only artifact that should grow next once a phase is built.
- No random AI content machine.
- No automation before repeated paid proof.
- No identity relitigation before the proof gate.
- No old SNIPED/BASEPLATE docs as current law (historical evidence only).
- No fake proof, no platform/registry claim, no photography-only reduction.
- No employer/confidential data or facility-sensitive imagery.

## 8. Reporting requirement for every major task

Claude must include, at the end of any major task:
- **Task category** (from section 3).
- **OS resources consulted.**
- **Corpus lanes activated.**
- **Tactical / tool docs consulted.**
- **Resources intentionally skipped and why.**
- **Output created.**
- **Proof-loop connection** (which PROOF_LOOPS hypothesis/test it serves).
- **Guardrails checked** (the standing list).

## 9. Escalation rule

If Claude cannot route a job through the OS, it must say:
> "I do not have enough routing clarity. I will inspect COMMAND_CENTER_COVERAGE_MANIFEST and relevant indexes before proceeding."
It must not guess. It inspects the manifest + relevant indexes, then routes.
