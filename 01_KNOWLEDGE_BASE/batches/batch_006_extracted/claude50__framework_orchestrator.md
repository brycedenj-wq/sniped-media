# Framework Orchestrator

**Category:** Meta-Skill (Cross-Framework Coordination)

## When to Use

When a problem is too complex for any single skill. The user presents a situation touching strategy, operations, economics, and execution, or asks broad questions like "analyze my business" or "what should I do." If the request maps to a single skill, use that skill directly instead.

## Instructions

Select relevant installed skills, execute them in a five-phase sequence, synthesize into one analysis. Do not invent frameworks — compose existing ones. Skip phases that add no value.

**Skill preferences by phase:**

- **Diagnose:** system-analysis-intervention-design, strategy-kernel-development, lean-transformation-diagnostic
- **Evaluate:** seven-powers-strategic-position-assessment, economic-incentive-policy-analysis, comparative-advantage-resource-allocation
- **Decide:** cognitive-bias-audit, munger-two-track-decision-analysis, premortem-analysis, superforecasting-workflow
- **Design:** strategy-kernel-development, value-stream-improvement-pdca, hoshin-kanri-goal-alignment
- **Communicate:** pyramid-structured-communication, success-message-design

## Workflow

1. **Classify the problem.** Strategic, operational, financial, decision-critical, technical, or hybrid.
2. **Select skills.** List relevant skills with one sentence each on why they apply.
3. **Sequence into phases.** A: Diagnose (what is happening). B: Evaluate (what forces are at work). C: Decide (confidence level, risks). D: Design (what to do). E: Communicate (structure the output). Skip empty phases.
4. **Execute each phase.** Run each skill's workflow. Carry outputs forward as inputs to the next phase.
5. **Synthesize.** Combine outputs into one document. Resolve contradictions explicitly — name the tension and recommend resolution.
6. **Deliver.** Use the output format below. End with next steps.

## Output Format

- **Situation Summary**: What was asked, problem type (2-3 sentences).
- **Skills Applied**: Which skills, why, in execution order.
- **Phase A — Diagnosis**: System map, named challenge.
- **Phase B — Evaluation**: Competitive position, economic dynamics.
- **Phase C — Decision Support**: Bias check, risk register, probability estimates.
- **Phase D — Design**: Strategy kernel, process improvements, goal alignment.
- **Phase E — Key Message**: Governing thought and 2-3 takeaways.
- **Tensions**: Where frameworks disagreed, how resolved.
- **Next Steps**: First action, open questions, which skills to run deeper.

Omit phases not relevant to the problem.

## Example Use

User: "50-person SaaS company, 40% growth, shrinking margins, competitor raised 100M, engineering burning out."

Skills selected: system-analysis-intervention-design (map growth-burnout loop), seven-powers-strategic-position-assessment (moat durability), cognitive-bias-audit (loss aversion check), strategy-kernel-development (build response).

Diagnosis: reinforcing loop where growth drives hiring pressure drives burnout drives attrition. Evaluation: moderate switching costs, no scale or network economies. Design: stabilize engineering before scaling, deepen switching costs via customer integrations. Key message: the internal system collapsing is the real threat, not the competitor's capital.
